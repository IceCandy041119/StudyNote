## 拓展1 三种交换方式的时延定量比较

**对应笔记**：1.1.4 电路交换、报文交换与分组交换。

设：报文总长度为 $x$ 比特，链路速率为 $b$（b/s），中间经过 $k$ 段链路，每段链路的传播时延为 $d$，分组长度为 $p$ 比特，电路交换的建立连接时间为 $s$。三种交换方式的总时延如下：

| 交换方式 | 总时延公式                                   | 说明                                                |
| ---- | --------------------------------------- | ------------------------------------------------- |
| 电路交换 | $s + \dfrac{x}{b} + kd$                 | 先建连（$s$），再连续发送（$x/b$），沿途传播（$kd$）；中间节点无存储转发时延      |
| 报文交换 | $k\left(\dfrac{x}{b} + d\right)$        | 每段链路都要「完整接收整个报文 → 再转发」，存储转发时延累加 $k$ 次             |
| 分组交换 | $\dfrac{x}{b} + kd + (k-1)\dfrac{p}{b}$ | 仅第 1 个分组要完整发送；中间 $k-1$ 个路由器每个只多等一个分组（$p/b$），形成流水线 |

**关键结论（统考高频）**：

1. **电路交换 vs 分组交换**：当 $s < (k-1)\dfrac{p}{b}$（建立连接时间小于分组交换的额外存储转发时延）时，电路交换总时延更小；反之分组交换更快。
2. **分组交换的「流水线」优势**：源端发完第 1 个分组后即可连续发送后续分组，中间路由器「边收边发」，因此当 $x \gg p$（报文远大于分组）时，分组交换的总时延远小于报文交换。
3. **报文交换最慢**：因为每个中间节点都要等完整报文到齐才能转发，$k$ 段链路时延逐段累加。

**考研提示**：408 常考「已知 $x$、$p$、$b$、$k$、$d$，比较两种交换方式总时延」「求电路交换优于分组交换的条件」等计算题，务必记住分组交换总时延中 $(k-1)\dfrac{p}{b}$ 这一项。

## 拓展2 数据报与虚电路

**对应笔记**：1.1.4 分组交换的失序问题。

分组交换在具体实现上分为两种服务方式，对应「无连接」与「面向连接」两种设计哲学：

| 对比项 | 数据报（Datagram） | 虚电路（Virtual Circuit） |
| --- | --- | --- |
| 连接 | 无连接，各分组独立传输 | 面向连接，先建立连接再传输 |
| 路径 | 每个分组独立选路，可走不同路径 | 连接建立时确定路径，同一条虚电路的分组走同一路径 |
| 顺序 | 可能失序，需目的主机按编号重排 | 有序到达 |
| 首部 | 需携带完整目的地址 | 只需携带简短的虚电路号 |
| 可靠性 | 网络尽最大努力交付 | 网络可提供一定的可靠性保障 |
| 故障应对 | 某节点故障可动态改走其他路径（灵活） | 某节点故障则整条虚电路需重建 |

**对应到 TCP/IP**：IP 协议采用**数据报**方式（无连接、不可靠、尽最大努力交付），这正是第 1 章强调的「IP 不可靠」的由来；而「虚电路」思想在早期的 X.25、帧中继、ATM 等网络中被采用。

**考研提示**：408 常考「数据报方式分组可能失序，虚电路方式有序」「两者首部开销差异」「故障应对灵活性」等对比点。

## 拓展3 TCP/IP 的「沙漏模型」

**对应笔记**：1.2.3 TCP/IP 模型、Everything over IP / IP over Everything。

TCP/IP 体系结构在工程上常被画成一只「沙漏」（hourglass）：

```
   应用层：HTTP  FTP  SMTP  DNS  RTP  …   （上层：协议众多）
        \          |          /
         \         |         /
           ┌──────────────┐
           │  网际层：IP   │   ←  窄腰（只有这一个协议）
           └──────────────┘
         /         |          \
   网络接口层：以太网  无线局域网  电话网  …  （下层：网络众多）
```

- **「窄腰」的意义**：中间只保留 **IP 一个协议**作为「通用转发格式」，上层无论什么应用（HTTP、DNS…）都封装成 IP 分组，下层无论什么物理网络（以太网、Wi-Fi、4G/5G…）都能承载 IP 分组。
- 这正是教材所说 **Everything over IP**（上层全部应用构建于 IP 之上）与 **IP over Everything**（IP 可运行于任意底层网络之上）的直观体现。
- **好处**：上层应用与下层网络「解耦」——新增一种应用（如新视频协议）不用改网络，新增一种物理网络（如新无线技术）也不用改应用，只需保证能传 IP 分组即可。

**考研提示**：理解沙漏模型有助于回答「为什么 IP 是互联网核心协议」「TCP/IP 为何能互联异构网络」等论述题。

## 拓展4 端到端原则

**对应笔记**：1.3 本章小结及疑难点（为什么 IP 不可靠互联网仍可靠）。

教材中「由端系统负责可靠性」的思想，其理论源头是 Saltzer、Reed 与 Clark 于 1984 年发表的著名论文 *End-to-End Arguments in System Design*（系统设计中的端到端原则）。

**核心主张**：

> 只有当一项功能**被通信的端系统（应用程序）**完整地、正确地实现时，它才算真正实现；若把它放在通信子系统（低层）里实现，那么对**所有**应用而言都很难做到完全正确——因为只有端系统才知道应用真正需要什么。

具体论据：

1. **可靠传输**：数据在「两端」之间传输，任何中间节点的确认都不能代表最终接收方已正确收到；真正的可靠性必须由两端核对（如 TCP 的确认、校验和、重传）。
2. **加密**：若只在链路上加密，数据在中间路由器处是明文，仍可能泄露；只有端到端加密才能保证全链路保密。
3. **数据去重/校验**：应用层才知道哪些数据是「真正重复的」，低层很难做对。

**代价与折中**：端到端原则并非绝对——低层实现某些功能（如数据链路层的 CRC 检错、拥塞控制的早期反馈）可以提升性能，作为「性能优化」是合理的；但**正确性必须由端到端保证**。这正是互联网把 IP 做成「尽力而为」、把可靠性交给 TCP 的原因。

**考研提示**：该原则是理解「IP 无连接不可靠 + TCP 端到端可靠」这一设计的底层逻辑，简答题/论述题可引用。

## 拓展5 常见网络设备的工作层次

**对应笔记**：1.2.3 OSI 参考模型各层功能。

把设备「钉」在 OSI 各层上，是第 1 章建立整体认知的关键（后续第 2～4 章会逐类详讲）：

| 设备 | 工作层次 | 通俗理解 |
| --- | --- | --- |
| 中继器（Repeater） | 物理层 | 放大/整形信号，延长传输距离，不识别数据含义 |
| 集线器（Hub） | 物理层 | 多端口中继器，一个端口收到的比特向所有端口广播 |
| 网桥（Bridge） | 数据链路层 | 依据 MAC 地址过滤/转发帧 |
| 交换机（Switch） | 数据链路层 | 多端口网桥，按 MAC 地址表转发帧 |
| 路由器（Router） | 网络层 | 依据 IP 地址查路由表，跨网络转发分组 |
| 网关（Gateway） | 传输层及以上 | 泛指高层协议转换/互连设备 |

**记忆口诀**：物理层——中继集线；链路层——网桥交换；网络层——路由；高层——网关。

**对应「名师论点：OSI 低三层的网络设备及其功能（2016）」**：集线器（物理层）、交换机（数据链路层）、路由器（网络层）分别对应 OSI 第 1、2、3 层，是常考的「设备—层次」匹配题。

**考研提示**：408 常考「某设备工作在 OSI 第几层」「集线器/交换机/路由器实现的最高功能层分别是物理层/数据链路层/网络层」。

## 拓展6 速率、带宽、吞吐量辨析

**对应笔记**：1.1.6 计算机网络性能指标（速率、带宽、吞吐量）。

三个概念极易混淆，本质区别在「标称 / 上限 / 实际」：

| 概念 | 本质 | 单位 | 类比 |
| --- | --- | --- | --- |
| 速率（数据率/比特率） | 节点在数字信道上**传送**数据的速率（标称/额定值） | b/s | 水龙头的标称流量 |
| 带宽 | ① 通信领域：信号频率范围；② 计算机网络：信道的**最高**数据传输速率（上限） | Hz / b/s | 水管的粗细（容量上限） |
| 吞吐量 | 单位时间内**实际**通过的数据量（受瓶颈限制） | b/s | 实际流出的水量 |

**关键结论**：

1. 端到端的**实际吞吐量 = 各段链路带宽与各设备处理速率中的最小值**（木桶效应），即瓶颈决定一切。教材原文即「节点间的实际可用带宽由双方网卡性能、各段链路带宽、交换设备速率中的最小值决定」。
2. 「带宽」在计网中已经由「频率范围」引申为「数据率」含义，做题时看到「带宽 100Mb/s」指的就是最高发送/传输速率。
3. 吞吐量 ≤ 带宽：带宽是理论上限，吞吐量是实际测得值，受拥塞、丢包、协议开销等影响。

**考研提示**：408 常考「带宽与速率的关系」「吞吐量由瓶颈决定」「网络带宽的实际值等于瓶颈链路带宽」等概念判断题。

## 拓展7 协议设计为何要「分层」

**对应笔记**：1.2.1 计算机网络分层结构。

分层并非唯一选择，但对复杂系统是最优解，理由可归纳为「分而治之 + 接口隔离 + 可替换」：

| 好处 | 说明 |
| --- | --- |
| 降低复杂度 | 把「大而复杂的问题」分解为若干「小而相对独立」的层，逐层研究 |
| 接口隔离 | 层与层之间只通过接口交互，内部实现互不干扰 |
| 可替换性 | 每层功能定义独立于实现，可换用更优技术而不影响其他层 |
| 利于标准化 | 各层职责明确，便于制定独立标准、不同厂商设备互联 |

**与「面向对象」的类比**（教材提到 OSI 分层思想与现代面向对象程序设计高度契合）：每一层相当于一个「对象」，只对外暴露「服务接口」（方法），内部实现细节对外「封装」「透明」，这正是软件工程中「高内聚、低耦合」思想在网络体系结构中的体现。

**反例核查**：分层也有代价——层间封装会增加首部开销（每层加 PCI）、可能带来冗余功能（如差错控制、流量控制在多层重复出现，见 1.2.3 表 1.2 中数据链路层/网络层/传输层都列有差错控制与流量控制）。这是分层设计的固有代价，原文在第 1 章未展开，特此补充。

**考研提示**：理解「体系结构是抽象的、实现是具体的」「上层单向使用下层服务、不能跨层调用」等表述的深层含义，有助于回答分层思想的优缺点论述题。
